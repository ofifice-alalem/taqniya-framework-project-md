## 📂 التفاصيل الهيكلية للأقسام

### 1. جذر المستودع (`/`)
* **`README.md`**: الملف التعريفي الرئيسي الذي يوضح غرض المستودع والعلاقة بين الفريم وتوثيق المشروع.

---

### 2. إطار العمل (`FRAMEWORK/`)
يحتوي على **Taqniya AI Development Framework** بكامل قواعده الهندسية وبروتوكولات الـ AI والـ Workflows والـ Templates.
> 💡 *هذا المجلد عام ولا يحتوي على أي تفاصيل تخص مشروعاً معيناً.*

---

### 3. توثيق المشروع (`PROJECT/MD/`)
يتم وضع هذا الهيكل داخل المشروع الحقيقي بمسار `PROJECT/MD/` ويحتوي على المعلومات المقسمة إلى **3 طبقات رئيسية**:

#### 🌐 الطبقة الأولى: المستوى العام للمشروع
* **`README.md`**: نقطة الدخول الشاملة لفهم المشروع، نطاقه، والنظرة العامة لملفات MD ومراحل العمل.
* **`stack.yaml`**: ملف تعريفي يحدد الـ Technology Stack الفعلي المستعمل (Frontend, Backend, Database, Auth, etc.).
* **`business_rules.md`**: قواعد العمل والشروط التجارية الشاملة التي تنطبق على جميع مراحل النظام.
* **`data.md`**: التصور العام للبيانات والكيانات الرئيسية والعلاقات المشتركة بين المراحل.
* **`design_rules.md`**: القيم البصرية الثابتة للمشروع (الألوان، الخطوط، Spacing، Radius، Shadow) دون إعادة تعريف المكونات.

#### 🤖 الطبقة الثانية: أدوات إدارة التوثيق (`prompts/`)
* **`Project_Recovery.md`**: استعادة حالة فهم المشروع وسياقه عند الانقطاع أو وجود تعارض.
* **`Module_Review.md`**: مراجعة وتدقيق جزء وظيفي أو Module محدد ومطابقته للتوثيق.
* **`Phase_Review.md`**: مراجعة وتقييم مرحلة كاملة وتحديد الفجوات والنواقص قبل الاعتماد.
* **`phases_prompt.md`**: الموجه الرئيسي لتوليد وإنشاء مراحل جديدة وتحديد نطاقها وملفاتها.

#### 📦 الطبقة الثالثة: التنفيذ الوظيفي للمراحل (`phases/`)
تُقسم إلى مراحل وظيفية (`phase_00_xxx`, `phase_01_xxx`, ...)، وتحتوي كل مرحلة على الملفات القياسية التالية:
* **`README.md`**: نطاق العمل، أهداف وتوقعات المرحلة، والاعتماديات.
* **`backend.md`**: متطلبات المعالجة والخدمات والـ Controllers والـ Domain Logic الخاصة بالمرحلة.
* **`frontend.md`**: مواصفات الشاشات والتفاعلات وحالات Loading/Error للواجهة الخاصة بالمرحلة.
* **`routes.md`**: تعريف API Endpoints والـ HTTP Methods والـ Parameters والصلاحيات للمرحلة.
* **`data.md`**: تفاصيل الكيانات والحقول والقيود والتغييرات الخاصة ببيانات هذه المرحلة فقط.

## 🎯 المميزات الرئيسية للهيكل

1. **فصل المسؤوليات:** الفصل التام بين قواعد الفريم المعيارية وتوثيق المشروع التطبيقي.
2. **قابلية التوسع والنمو:** تنظيم المراحل داخل `phases/` يسهل التعديل والتوسع المستقبلي بشكل معياري.
3. **أقصى كفاءة للذكاء الاصطناعي:** تزويد الـ AI بسياق دقيق ومنظم يمنع التشتت والهلوسة ويضمن جودة الكود والتوثيق.
