# 🤖 Prompt: Execute Phase (موجّه تنفيذ المرحلة عبر محرك التنفيذ المعتمد)

> **الغرض:** يُستخدم لتسليم سياق المرحلة المحلول وقواعدها ومعايير قبولها إلى **محرك التنفيذ المعتمد (Configured Execution Engine)** ليقود التنفيذ البرمجي.  
> **المبدأ المعماري الصارم:** تفصل تقنية تماماً بين تحديد المتطلبات (WHAT) وآلية التنفيذ (HOW). هذا الموجّه لا يفرض منهجيات عمل داخلية (مثل TDD أو أسلوب تخطيط محدد)، بل يُسلّم حزمة الحوكمة للمحرك المختار في `PROJECT/MD/execution_engine.yaml` ليدير دورة تنفيذه الخاصة.

---

## 📝 تعليمات التنفيذ للـ AI Agent

قم بتجهيز وتسليم سياق المرحلة المحددة: `[أدخل اسم أو مسار مجلد المرحلة]`

### 1. تجهيز وتسليم حزمة الحوكمة للمرحلة (Resolved Governance Payload)
اجمع وسلّم المحرك المعتمد الحزمة المعمارية الكاملة:
- **وثائق مواصفات المرحلة:** (`README.md`, `backend.md`, `frontend.md`, `routes.md`, `data.md`, `testing.md`).
- **القواعد المرجعية والبروفايلات:** (`06_stack_profiles/`, `00_core/*`).
- **مخطط البيانات المعتمد:** (`PROJECT/MD/database.md`).
- **سياسات الأداء:** (`PROJECT/MD/frontend_capabilities.yaml`).
- **قواعد الصلاحيات والأمان:** (`00_core/security_rules.md`).
- **شروط القبول ومعايير الاكتمال المطلوبة:** (Acceptance Criteria & Definition of Done).

### 2. تفويض محرك التنفيذ المعتمد (Execution Engine Delegation)
- يتولى المحرك المختار في `PROJECT/MD/execution_engine.yaml` (أو `native` تلقائياً عند غياب الملف) قيادة التنفيذ وفق آلياته ومنهجياته الخاصة (Planning, Coding, Testing Loops, Debugging).
- **الالتزام الإلزامي من المحرك:**
  - الالتزام التام بالهيكل المعماري المعلن في `stack.yaml`.
  - الالتزام الصارم بحدود الطبقات (Layer Boundaries) ومنع التسريب بين الواجهات وقواعد البيانات.
  - الالتزام بنظام التصميم ورموز الألوان وسياسات الأداء.

### 3. إشعار إتمام التنفيذ البرمجي
- عند انتهاء محرك التنفيذ من كتابة الكود واجتياز فحوصاته الذاتية، يُعلن اكتمال التنفيذ البرمجي.
- يتم الانتقال فوراً إلى مرحلة التدقيق والتحقق المستقل عبر موجّه `review_phase.md`.
