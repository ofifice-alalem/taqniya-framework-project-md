# 🤖 Prompt: Design Database (موجّه تصميم مخطط قاعدة البيانات)

> **الغرض:** يُستخدم لتحويل قواعد العمل وكيانات البيانات إلى مخطط هندسي تفصيلي وموثق في `database.md`.  
> **القاعدة الذهبية:** هذا المخطط هو المرجع الأوحد (SSoT) لهيكل البيانات، ويمنع منعاً باتاً اختراع أي جداول عشوائية لاحقاً أثناء البرمجة.

---

## 📝 تعليمات التنفيذ للـ AI Agent

قم ببناء أو تحديث التوثيق المعماري لقاعدة البيانات في `PROJECT/MD/database.md`:

### 1. المدخلات المرجعية الإلزامية
- اقرأ قواعد العمل من `PROJECT/MD/business_rules.md`.
- اقرأ مفاهيم الكيانات من `PROJECT/MD/data.md`.
- اقرأ محرك وقواعد التخزين المعتمدة في `PROJECT/MD/stack.yaml`.

### 2. تصميم المخطط التفصيلي (Schema Blueprint)
لكل جدول في النظام، حدد بدقة متناهية:
1. **اسم الجدول (Table Name):** التسمية القياسية الموحدة (مثل الجمع بصيغة snake_case).
2. **الأعمدة وأنواع البيانات (Columns & Strict Types):** (مثل `uuid`, `bigint unsigned`, `varchar(255)`, `decimal(12,2)`, `timestamp`, إلخ).
3. **المفاتيح الأساسية والأجنبية (Keys):** Primary Keys، Foreign Keys والعلاقات المرتبطة بها.
4. **القيود الصارمة (Constraints):** `NOT NULL`، `UNIQUE`، `CHECK` constraints، والقيم الافتراضية.
5. **الفهارس وتحسين الأداء (Indexes):** فهارس البحث والتصفية المتكررة وفهارس الأعمدة المركبة (Composite Indexes).
6. **سلوك الحذف والتحديث (Cascade Rules):** `onDelete('cascade')`، `onDelete('restrict')`، أو استراتيجيات الـ Soft Deleting.

### 3. حفظ المخطط في `PROJECT/MD/database.md`
- اكتب أو حدّث ملف `PROJECT/MD/database.md` بجميع الجداول والعلاقات بصيغة Markdown واضحة ومنظمة.
- اطلب مراجعة واعتماد المطور للمخطط قبل الانتقال لتنفيذ الـ Migrations.
