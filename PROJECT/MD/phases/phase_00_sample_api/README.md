# 📦 Phase 00: Sample API Phase (نموذج مرحلة قياسي — نمط API-First)

> **الملف التعريفي والتوجيهي الرئيسي للمرحلة القياسية التوضيحية بنمط واجهات برمجة التطبيقات (API-First).**

---

## 📌 1. بطاقة تعريف المرحلة (Phase Metadata)

- **اسم المرحلة البرمجي:** `phase_00_sample_api`
- **عنوان المرحلة:** إدارة الكيان القياسي (Sample Resource Management).
- **نمط الاتصال المعماري:** `API-First` (`mode: api_first` في `MD/stack.yaml`).
- **حالة المرحلة:** 🟡 نموذج توضيحي وإرشادي (Reference Template).
- **الهدف العام:** تقديم نموذج معياري موحد يوضح كيفية تنظيم وصياغة ملفات المواصفات للمراحل الوظيفية المبنية بنمط API، بما يحقق الفصل الكامل للمسؤوليات (Separation of Concerns) ويمنع تكرار التوثيق (DRY).

---

## 🎯 2. نطاق العمل (Scope of Work)

### 🟢 ما تشمله المرحلة (In-Scope):
- توفير واجهات برمجة تطبيقات RESTful كاملة لإدارة الكيان (إنشاء، عرض، تعديل، وحذف منطقي).
- توفير واجهات مستخدم تفاعلية متجاوبة ومتصلة بالـ API مع معالجة كافة حالات الاستجابة والأخطاء.
- توثيق المخطط الهيكلي للجداول، والعلاقات، والفهارس، ودورة حياة الحالات.
- تطبيق المعاملات الذرية (ACID Transactions)، والتحقق الصارم عند الحدود، وحماية الصلاحيات وعزل المستأجرين.
- تغطية شاملة لكافة حالات الـ HTTP والأخطاء وهياكل الـ JSON.

### 🔴 ما لا تشمله المرحلة (Out-of-Scope):
- العمليات المتقدمة الخاصة بالمراحل اللاحقة.
- تعديل أو استحداث جداول خارج المخطط المعتمد في `MD/database.md`.
- هذه المرحلة مخصصة كقالب ومرجع معياري لكتابة المواصفات في المشروع.

---

## 📁 3. خارطة ملفات مواصفات المرحلة (Phase Specification Map)

تتكامل وثائق المرحلة فيما بينها وفق مبدأ فصل المسؤوليات:

| الملف | المسؤولية والدور المعماري | المحتوى الرئيسي |
| :--- | :--- | :--- |
| **`README.md`** | **الملخص ودليل المرحلة** | بطاقة التعريف، نطاق العمل، الاعتماديات، ومعايير القبول العامة. |
| **`routes.md`** | **عقد الشبكة والـ API (Network SSoT)** | خريطة الـ Endpoints، الترويسات، وهياكل الـ JSON الكاملة لجميع استجابات النجاح والفشل. |
| **`backend.md`** | **منطق الأعمال والنزاهة الداخلية** | قواعد التحقق، المعاملات الذرية (ACID)، المعايير المالية، الأحداث، وعزل المستأجرين. |
| **`frontend.md`** | **واجهات وتجارب المستخدم** | الشاشات، نظام التصميم و `dir="rtl"`، قدرات الواجهة، وحالات الشاشات الأربع. |
| **`data.md`** | **البيانات ومخطط الكيانات** | بنية الجداول، العلاقات، الفهارس، مخطط الـ ERD، ومصفوفة الحالات (State Machine). |
| **`testing.md`** | **مصفوفة الاختبارات** | اختبارات الوحدة، اختبارات الـ API، واختبارات المعاملات والتراجع. |
| **`checklist.md`** | **قائمة التحقق والاكتمال** | بنود التحقق التفصيلية للتأكد من جاهزية المرحلة للاعتماد. |

## 🔗 4. الاعتماديات والمراجع العامة (Dependencies & SSoT)

تعتمد هذه المرحلة على المراجع والسياسات العامة للمشروع:
- `MD/stack.yaml`: التقنيات المعتمدة، حزم الاختبار، ونمط الاتصال (`api_first`).
- `MD/database.md`: مخطط قاعدة البيانات المعتمد ومصدر الحقيقة للجداول.
- `MD/business_rules.md`: قواعد وسياسات العمل والمصطلحات العامة للنظام.
- `MD/design_rules.md`: رموز ونظام التصميم للألوان والمسافات والخطوط.
- `MD/frontend_capabilities.yaml`: سياسات وقدرات الواجهة المفعلة والإلزامية.
