# 🤖 Prompt: Analyze Phase (موجّه تحليل وتفكيك المرحلة الوظيفية)

> **الغرض:** يُستخدم لتحليل المرحلة الوظيفية المستهدفة وتحديد نطاقها ومتطلباتها واختباراتها ومخاطرها قبل كتابة أي سطر كود.  
> **حدود الصلاحية:** هذا الموجّه تحليلي وتخطيطي بحت؛ ولا يقوم بكتابة أو تعديل الكود الفعلي.

---

## 📝 تعليمات التنفيذ للـ AI Agent

قم بتحليل المرحلة المحددة: `[أدخل اسم أو مسار مجلد المرحلة مثل PROJECT/MD/phases/phase_01_sample/]`

### 1. قراءة واستيعاب مواصفات المرحلة
- اقرأ وثائق المرحلة المستهدفة بالكامل (`README.md`, `backend.md`, `frontend.md`, `routes.md`, `data.md`, `testing.md`).
- طابق متطلبات المرحلة مع المواصفات العامة:
  - قواعد العمل: `PROJECT/MD/business_rules.md`
  - مخطط قاعدة البيانات: `PROJECT/MD/database.md`
  - قيود التصميم والواجهة: `PROJECT/MD/design_rules.md`
  - سياسات الأداء: `PROJECT/MD/frontend_capabilities.yaml`
  - التقنيات المعتمدة: `PROJECT/MD/stack.yaml`

### 2. إعداد تقرير تحليل أثر المرحلة (Phase Impact Analysis)
أصدر وثيقة تحليلية تغطي بدقة:
1. **نطاق التسليمات (Scope of Deliverables):** ما الذي يجب إنجازه بالتحديد في هذه المرحلة وما الذي يقع خارج نطاقها؟
2. **الملفات والمكونات المتأثرة (Target Files & Components):** قائمة الملفات التي سيتم إنشاؤها أو تعديلها عبر الـ Backend, Frontend, Routing, State.
3. **التبعيات المعمارية (Architectural Dependencies):** الترتيب المنطقي للبرمجة (البيانات ➔ منطق العمل ➔ واجهات الـ API ➔ الواجهات البصرية).
4. **المخاطر والحالات الحدية (Risks & Edge Cases):** نقاط التعقيد المحتملة والتعامل مع الأخطاء.
5. **خطة الاختبارات المطلوبة (Testing Strategy):** متطلبات اختبارات الوحدة، اختبارات الميزات، واختبارات التكامل المحددة للمرحلة.
6. **معايير الاكتمال (Definition of Done):** قائمة الشروط الصريحة لاعتبار المرحلة مكتملة بنجاح.

### 3. الاعتماد
اعرض هذا التقرير التحليلي على المطور، وبمجرد اعتماده انتقل لتنفيذ المرحلة عبر موجّه `execute_phase.md`.
